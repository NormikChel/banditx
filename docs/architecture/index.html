Архитектура

Как устроен код, какие зависимости используются.

banditx — один бинарь на Rust. Асинхронный рантайм — tokio. Вся работа с сетью — через async/await без блокирующих вызовов.

Ключевые крейты

  • tokio — асинхронный рантайм и сеть
  • rustls + ring — TLS 1.2 и 1.3, ALPN, чистый Rust
  • h2 — серверная и клиентская реализация HTTP/2
  • httparse — парсинг HTTP/1.1, на нём же сидят hyper и reqwest
  • serde_yaml — парсинг конфига
  • arc-swap — атомарная подмена конфига при hot-reload
  • notify — слежение за файлом конфига
  • flate2 — gzip

Жизненный цикл запроса

На входе — TCP-соединение. Если включён TLS, происходит ALPN-хендшейк и выбирается протокол. Дальше — либо HTTP/1.1 keep-alive цикл, либо HTTP/2-сессия с множеством потоков. Маршрут ищется по самому длинному совпадающему префиксу. Дальше — статика, FastCGI или HTTP-апстрим. Ответ стримится обратно без полной буферизации.

Структура модулей

  • config — YAML, hot-reload, .banditx-файлы
  • http1 — парсинг, framing, response building
  • http2 — сервер и клиент HTTP/2
  • upstream — пулы соединений, балансировка, health checks, FastCGI
  • server — приём соединений, TLS, client loop
  • middleware — gzip, статика, rate limit
  • metrics — счётчики и Prometheus-выдача

Что дальше

Проект в статусе пет-проекта. Работает, но не обкатан в продакшене. Если используешь — держи рядом nginx на случай странностей.
