Конфиг — это один файл banditx.yaml. Никаких include, никаких скриптов, никакой магии. Всё, что делает прокси, описано в этом файле.

#Минимальный конфиг

Этого достаточно, чтобы проксировать example.com на локальный бэкенд по HTTPS через встроенный ACME.

#Секция server

ℹworkers: 0

banditx асинхронный (tokio). Вместо форка процессов он поднимает воркеров на потоках. Обычно 0 (auto) — правильный выбор.

#Секция listeners

Каждый listener — это отдельный bind с опциональным TLS и HTTP/2. Для 80 и 443 можно сделать два listener'а и один редирект-роут.

#Секция routes

Роуты матчатся сверху вниз. Первый, чьё правило совпало — выигрывает. Порядок в файле значим.

#Переменные окружения

Любое значение в конфиге можно подставить из окружения через ${VAR} или ${VAR:-default}. Работает для секретов и портов.

#Валидация

Перед применением конфига всегда полезно прогнать его через check. Он ловит опечатки, несуществующие ссылки и несовместимые флаги.

⚠Рекурсивные ссылки

Если route ссылается на upstream, который ссылается на route — check выругается и не даст запустить. Так задумано.

#Горячий reload

SIGHUP перечитывает конфиг без разрыва активных соединений. Слушающие сокеты переиспользуются, upstream-пулы пересобираются, новые правила вступают в силу мгновенно.
