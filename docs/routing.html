Маршрутизация

Host, path, regex, headers, приоритеты, redirect и rewrite — с примерами.

Роутинг — сердце banditx. Правила простые, но выразительные. Здесь всё, что можно написать в routes:.

#Что можно матчить

ПолеПримерЧто делает
hostapi.example.comточное совпадение по Host (регистронезависимо)
host_regex^.*\.example\.com$regex по Host
path_prefix/v1префикс пути
path_regex^/users/\d+$regex по пути
methodPOST,PUTметод HTTP
headerAuthorization: Bearer *матч по заголовку (glob)
querydebug=1наличие query-параметра
listenerhttpтолько для конкретного listener'а
ℹAND по умолчанию

Все перечисленные условия в одном match: объединяются через AND. Если нужно OR — делай два роута.

#Приоритеты

Правила обрабатываются сверху вниз, побеждает первое совпадение. Есть два способа управлять порядком: физический порядок в файле и явный priority.

⚠Anti-pattern

Не делай 30 роутов с одинаковым match и разными priority. Это работает, но читать такое больно. Лучше разбей по listener'ам или субдоменам.

#Redirect и rewrite

Роут может не проксировать, а редиректить. Поддерживаются переменные: $host, $request_uri, $scheme, $remote_addr.

#Заголовки

Заголовки можно добавлять, перезаписывать и удалять. Работает и на запрос, и на ответ.
