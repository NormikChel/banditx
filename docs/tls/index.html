banditx умеет два сценария: подсунуть свои сертификаты или попросить Let's Encrypt выпустить их автоматически. Оба можно совмещать: для одного домена — ACME, для другого — свой wildcard.

#Статические сертификаты

ℹПорядок сертификатов

cert_file должен содержать цепочку: сначала листовой сертификат, потом промежуточные CA. Это стандарт, но иногда его путают с cat server.crt ca.crt.

#ACME / Let's Encrypt

Встроенный ACME-клиент умеет HTTP-01 и TLS-ALPN-01. Никакого certbot, никаких cron'ов. Сертификаты обновляются автоматически за 30 дней до истечения.

⚠Staging для тестов

При разработке используй staging-URL https://acme-staging-v02.api.letsencrypt.org/directory. У LE есть жёсткие rate limits, и в лоб их легко поймать.

#SNI и несколько доменов

SNI-роутинг раздаёт разные сертификаты разным хостам на одном listener'е. ACME-блок можно указать несколько — прокси сам определит, какой сертификат отдавать.

#mTLS (клиентские сертификаты)

Для внутренних API удобно закрывать всё клиентским сертификатом. banditx проверяет цепочку и (опционально) CN.

#HSTS и заголовки безопасности

✕preload необратим

Если отправил домен в hstspreload.org, отозвать его можно месяцами. Сначала протестируй с max-age=300.

#OCSP Stapling

Включено по умолчанию для статических сертификатов. Для ACME — тоже, без настроек.
