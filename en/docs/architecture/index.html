Architecture

How the code is built, what dependencies are used.

banditx is a single Rust binary. Async runtime is tokio. All network work goes through async/await, no blocking calls.

Key crates

  • tokio — async runtime and network
  • rustls + ring — TLS 1.2 and 1.3, ALPN, pure Rust
  • h2 — server and client HTTP/2 implementation
  • httparse — HTTP/1.1 parsing, the same one hyper and reqwest use
  • serde_yaml — config parsing
  • arc-swap — atomic config swap on hot reload
  • notify — config file watching
  • flate2 — gzip

Request lifecycle

On input — a TCP connection. If TLS is on, an ALPN handshake picks the protocol. Then either an HTTP/1.1 keep-alive loop or an HTTP/2 session with many streams. The route is looked up by the longest matching prefix. Then it is static files, FastCGI, or an HTTP upstream. The response streams back without full buffering.

Module structure

  • config — YAML, hot reload, .banditx files
  • http1 — parsing, framing, response building
  • http2 — HTTP/2 server and client
  • upstream — connection pools, balancing, health checks, FastCGI
  • server — connection accept, TLS, client loop
  • middleware — gzip, static files, rate limit
  • metrics — counters and Prometheus exposition

Status

The project is a pet project. It works, but it is not battle-tested in production. If you use it, keep nginx nearby in case of surprises.
