Routing

Host, path, regex, headers, priorities, redirect and rewrite — with examples.

Routing is the heart of banditx. Rules are simple but expressive. Here's everything that can go into routes:.

#What you can match

FieldExampleWhat it does
hostapi.example.comexact Host match (case-insensitive)
host_regex^.*\.example\.com$regex against Host
path_prefix/v1path prefix
path_regex^/users/\d+$regex against path
methodPOST,PUTHTTP method
headerAuthorization: Bearer *header match (glob)
querydebug=1query param presence
listenerhttponly on a specific listener
ℹAND by default

All conditions in one match: are AND-ed. If you need OR — write two routes.

#Priorities

Rules are processed top-down, the first match wins. Two ways to control order: physical order in the file, or explicit priority.

⚠Anti-pattern

Don't create 30 routes with the same match and different priority. It works, but reading it hurts. Split by listener or subdomain instead.

#Redirect and rewrite

A route can redirect instead of proxying. Variables supported: $host, $request_uri, $scheme, $remote_addr.

#Headers

Headers can be added, overwritten and removed. Both request and response.
